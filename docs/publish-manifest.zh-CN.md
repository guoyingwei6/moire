# 受管理的发布清单

> 当前状态：macOS 导出器的构建步骤会写入受管理的清单和协调报告。报告是非破坏性的；系统不会自动执行清理删除。

Apple Notes 导出是一条单向发布工作流，但生成的网站仍应能够识别已经删除、重命名或移动的已发布笔记。因此，Moire 保留 `content/.moire-manifest.json` 作为机器写入的所有权记录。它不是 Apple Notes 设置，作者永远不需要手动编辑它。

## 保护隐私的格式

```json
{
  "version": 1,
  "root": "sha256-of-the-fixed-public-root-binding",
  "files": [
    {
      "path": "blog/example.md",
      "kind": "markdown",
      "digest": "sha256-of-the-generated-file"
    },
    {
      "path": "media/example.jpg",
      "kind": "media",
      "digest": "sha256-of-the-generated-file"
    }
  ]
}
```

清单不包含笔记正文、凭据或私有 Notes 标识符。`root` 严格是固定公开 FolderEntity 绑定的小写 SHA-256 指纹，绝不会保存其可读名称或原始标识符。路径均相对于 `content/`。它们必须经过 Unicode 规范化，即使忽略大小写也必须唯一，并且不得包含绝对路径前缀、空路径段、`.`/`..`、反斜杠、查询参数、片段或控制字符。清单不能声明自己归其所有。`markdown` 条目必须以 `.md` 结尾；`media` 条目必须直接位于 `media/` 下，并使用渲染器当前支持的图片扩展名。这可以防止伪造或过期的清单把删除权限扩大到不相关的仓库文件。

## 协调顺序

当前 macOS 导出器的构建步骤按以下顺序运行：

1. 读取 `notes-export/public-notes.json`。
2. 解析唯一固定的公开根，并解析其中唯一有效的 `index` 菜单。
3. 生成允许列表中的全部 Markdown 和媒体文件，然后计算生成字节的 SHA-256 摘要。
4. 读取并严格验证上一份清单。清单不存在表示首次运行；清单格式错误、版本不受支持或根指纹不同都会使构建停止。
5. 写入下一份 `content/.moire-manifest.json`。
6. 写入 `content/.moire-reconcile.json`，其中包括：
   - `upsert`：新增或发生变化的生成文件；
   - `unchanged`：字节完全相同的生成文件；
   - `remove`：上一份清单中存在、但下一份清单中不存在的文件；
   - `relocate`：类型和摘要相同的 remove/upsert 配对，通常是重命名或移动候选项。

当前实现特意在此停止。它不会把任何仓库内容作为清理操作删除。

如果以后启用清理，必须使用以下顺序：

1. 读取并验证两份清单。
2. 只删除上一份有效清单中存在、但下一份清单中不存在的路径。路径本来就不存在视为幂等成功；其他任何仓库文件都没有删除资格。
3. 最后写入新清单并报告完成。

## 未来使用 GitHub Contents API 的顺序

如果发布器以后从提交原始快照改为直接通过 GitHub Contents API 写入，应使用同样的安全顺序：

1. 解析唯一固定的公开根，并解析其中唯一有效的 `index` 菜单。
2. 解析允许列表中的每个 FolderEntity，收集全部笔记，并在第一次写入 GitHub 之前在本地验证所有目标路径。
3. 将当前处理的全部 Markdown 和媒体转换为确定性字节，并计算 SHA-256 摘要。
4. 读取并严格验证上一份清单。清单不存在表示首次运行；清单格式错误、版本不受支持或根指纹不同都会使同步停止。
5. 上传新增或发生变化的媒体，再上传新增或发生变化的 Markdown。
6. 只删除上一份有效清单中存在、但下一份清单中不存在的路径。路径本来就不存在视为幂等成功；其他任何仓库文件都没有删除资格。
7. 最后写入新清单并报告完成。

最后写入清单，可以让网络中断后的重试保持安全。该协议能够实现最终收敛，但不能保证单次提交的原子性：GitHub Contents API 每次请求都会创建一个提交。以后可以改用 Git Data API，在不改变所有权规则的情况下，让完整批次具备原子性。

## 上线门槛

纯验证与协调规则位于 `src/lib/sync/publish-manifest.js`，并有确定性单元测试。规则本身不会删除任何内容。当前导出器使用这些规则写入清单和报告。未来任何清理模式仍然需要所有者另行决定，因为它会把仅报告的 remove 候选项变成实际的仓库删除。
